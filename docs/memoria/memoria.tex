\section{Introducción}
Esta memoria recoge el desarrollo del proyecto de la asignatura \textit{Arquitectura de Computadores}, impartida en el curso 2025-2026 en la Escuela de Ingeniería Informática de Oviedo. El proyecto tiene como objetivo aplicar los conocimientos adquiridos en la asignatura para diseñar e implementar un filtro de imágenes en lenguaje \texttt{C/C++}. Además, se ha de analizar el rendimiento del filtro y compararlo con las implementaciones monohilo y multihilo.\vspace{2ex}

\noindent El trabajo se ha estructurado en varias fases progresivas:
\begin{itemize}
    \item \textbf{Entrega 1 (Monohilo):} Implementación básica del filtro de imágenes en un solo hilo.
    \item \textbf{Entrega 2 (SIMD y Multihilo):} Optimización del filtro utilizando instrucciones SIMD y paralelización con múltiples hilos.
\end{itemize}
\vspace{3ex}

    if (access(filename, F_OK) == -1) {
        fprintf(stderr, "Error: la imagen '%s' no existe.\n", filename);
        exit(EXIT_FAILURE);
    }

    CImg<data_t> image(filename); 
    return image;
}
\end{lstlisting}

Este método recibe en forma de parámetro el nombre del archivo y llama a la 
función \texttt{access()} con el nombre del archivo y el parámetro \texttt{F\_OK}. 
Si la imagen no existe, la función \texttt{access()} devuelve \(-1\) y se muestra
un mensaje de error por pantalla y se termina la ejecución del programa.
\vspace{2ex}

y se devuelve. También se ha de comprobar que las dimensiones de la imagen

\subsection{Implementación de algoritmo}

El algoritmo a implementar ha sido el de inversión de blanco y negro. Para ello implementamos 
la función filter,  esta para cada pixel 
de la imagen multiplica cada componente del imagen original por su correspondiente peso, suma estos 
y lo atribuye a una variable \texttt{L} de tipo \texttt{double}.  Los pesos son los siguientes:
\begin{enumerate}
    \item Componente roja: Esta ha de ser multiplicada por \(0.3\)
    \item Componente verde: Esta ha de ser multiplicada por \(0.59\)
    \item Componente azul: Esta ha de ser multiplicada por \(0.11\)
\end{enumerate}

Por último hay que realizar la inversión de colores, es por 
ello  hay que restar el valor obtenido a \(255\) (valor máximo de brillo)
y asignar este valor a las tres componentes de cada pixel de la imagen destino.
Como esto tiene que hacerse para cada pixel, realizamos un bucle 
que recorre todos los pixeles de la imagen. A contiuación se muestra un fragmento 
de código de la función:

\begin{lstlisting}[style=cppStyle]
void filter (filter_args_t args) {
    for (uint i = 0; i < args.pixelCount; i++) {
        data_t L = *(args.pRsrc + i) * R_WEIGHT + 
                *(args.pGsrc + i) * G_WEIGHT + 
                *(args.pBsrc + i) * B_WEIGHT;
        
        L = MAX_BRIGHTNESS - L;

        *(args.pRdst + i) = L;
        *(args.pGdst + i) = L;
        *(args.pBdst + i) = L;
    }
}
\end{lstlisting}

Como el tiempo debía estar entre 8 y 15 segundos, hemos realizado un bucle de 125 
iteraciones de la función filter para que el tiempo de ejecución del programa esté dentro de este rango.
\vspace{3ex}
\begin{lstlisting}[style=cppStyle]
  for (int i = 0; i < N_ITERATIONS; i++){
		filter(filter_args);
	}
\end{lstlisting}

\section{Flujo de trabajo y metodología de desarrollo}
Todo el desarrollo del proyecto se puede seguir en el repositorio de \textit{GitHub}: \href{https://www.github.com/Mendana/teamwork-ac-2025}{ver repositorio}. Para la gestión del proyecto y poder garantizar un desarrollo colaborativo, se ha establecido un flujo de trabajo común basado en \textit{Git} y \textit{GitHub} como herramientas centrales de organización y control de versiones. Los aspectos clave son:
\begin{itemize}
    \item \textbf{Repositorio compartido:} con el código, documentación y recursos del proyecto.
    \item \textbf{Issue:} cada tarea se define como una \textit{issue} en \textit{GitHub}, con un responsable y un \textit{deadline}.
    \item \textbf{Project Board:} se emplea un tablero \textit{Kanban} con columnas \textit{To Do}, \textit{In Progress}, \textit{Review} y \textit{Done} para visualizar el estado de las tareas.
    \item \textbf{Milestones:} cada entrega del proyecto se ha asociado a un \textit{milestone} que agrupa las \textit{issues} correspondientes a dicha fase.
    \item \textbf{Pull Requests:} todas las contribuciones se realizan mediante \textit{pull requests} que deben ser revisadas y aprobadas por, al menos, 3 de los 4 miembros del equipo antes de integrarse en \texttt{main}.
    \item \textbf{Documentación:} se guarda la documentación en la carpeta \texttt{docs/}.
\end{itemize}
\vspace{2ex}

\subsection{Metodología}
\label{anexo:metodologia}
El equipo ha adoptado una metodología ágil adaptada al contexto académico del proyecto, inspirada en un enfoque híbrido entre \textit{Scrum} y \textit{Kanban}. Los aspectos clave de esta metodología son:
\begin{itemize}
    \item La planificación se organiza en \textbf{iteraciones} (\textit{milestones}) correspondientes a las entregas del proyecto.
    \item Las tareas se dividen en \textbf{issues} manejables y se priorizan según su importancia y dependencia. Estas tareas son asignadas a los miembros del equipo.
    \item El \textbf{project board} permite al equipo visualizar el progreso y gestionar las tareas de manera eficiente.
    \item La revisión colectiva de los \textit{pull requests} fomenta la calidad del código y el aprendizaje compartido.
    \item Las dependencias entre issues se gestionan mediante etiquetas y referencias cruzadas en \textit{GitHub}.
\end{itemize}
