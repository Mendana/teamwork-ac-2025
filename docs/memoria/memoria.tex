\section{Introducción}
La presente memoria recoge el desarrollo del proyecto correspondiente a la asignatura \textit{Arquitectura de Computadores}, impartida durante el curso académico 2025-2026 en la Escuela de Ingeniería Informática de Oviedo. El objetivo del proyecto es aplicar los conocimientos adquiridos en la asignatura para diseñar e implementar un filtro de imágenes en lenguaje \texttt{C/C++}. Asimismo, se realiza un análisis del rendimiento del filtro y una comparación entre las versiones monohilo y multihilo.\vspace{2ex}

\noindent El trabajo se ha estructurado en distintas fases progresivas:
\begin{itemize}
    \item \textbf{Entrega 1 (Monohilo):} Implementación básica del filtro de imágenes en un único hilo de ejecución.
    \item \textbf{Entrega 2 (SIMD y Multihilo):} Optimización del filtro mediante el uso de instrucciones SIMD y la paralelización con múltiples hilos.
\end{itemize}
\vspace{3ex}

\section{Desarrollo del algoritmo}
Se desarrolló el algoritmo de inversión en blanco y negro (Algoritmo número \#3). El desarrollo se realizó utilizando la máquina virtual proporcionada por el profesorado, junto con la plantilla base facilitada.\vspace{2ex}

\noindent La plantilla incluía las líneas de código necesarias para obtener el número de píxeles, así como los punteros a los arreglos RGB de las imágenes de entrada y salida. Por tanto, fue necesario únicamente implementar las comprobaciones y el algoritmo principal.

\subsection{Comprobaciones e inicialización}
Antes de implementar el algoritmo, se llevaron a cabo las comprobaciones necesarias para verificar la existencia del archivo de imagen y la correcta inicialización de las variables. La comprobación de existencia se realiza mediante la siguiente función:

\begin{lstlisting}[style=cppStyle]
CImg<data_t> load_image(const char* filename) {
    if (access(filename, F_OK) == -1) {
        fprintf(stderr, "Error: la imagen '%s' no existe.\n", filename);
        exit(EXIT_FAILURE);
    }

    CImg<data_t> image(filename); 
    return image;
}
\end{lstlisting}

Esta función recibe como parámetro el nombre del archivo y emplea la llamada \texttt{access()} con el parámetro \texttt{F\_OK}. Si la imagen no existe, la función devuelve \(-1\), se muestra un mensaje de error en la salida estándar y finaliza la ejecución del programa.\vspace{2ex}

En caso de existir el archivo, se crea un objeto de la clase \texttt{CImg} y se devuelve. Adicionalmente, se comprueba que las dimensiones y el espectro de la imagen de salida coincidan con los de la imagen original:

\begin{lstlisting}[style=cppStyle]
if (static_cast<unsigned int>(dstImage.width()) != width || 
    static_cast<unsigned int>(dstImage.height()) != height || 
    static_cast<unsigned int>(dstImage.spectrum()) != nComp) {
    fprintf(stderr, "Error: las dimensiones de la imagen de salida no coinciden con la original.\n");
    free(pDstImage);
    exit(EXIT_FAILURE);
}
\end{lstlisting}
\vspace{2ex}

En caso de discrepancia, se muestra un mensaje de error y se detiene la ejecución del programa.
Asimismo, se modificó el tipo de dato empleado de \texttt{float} a \texttt{double}. Se definieron también los pesos para las componentes de color y el brillo máximo, como se muestra a continuación:

\begin{lstlisting}[style=cppStyle]
#define R_WEIGHT 0.3
#define G_WEIGHT 0.59
#define B_WEIGHT 0.11
#define MAX_BRIGHTNESS 255.0
\end{lstlisting}
\vspace{2ex}

Para medir el tiempo de ejecución, se emplearon las funciones \texttt{clock\_gettime()} con los parámetros \texttt{CLOCK\_REALTIME} y las direcciones de memoria de las variables temporales. En caso de error, se muestra un mensaje y se finaliza la ejecución:

\begin{lstlisting}[style=cppStyle]
if(clock_gettime(CLOCK_REALTIME, &tStart) == -1) {
    printf("Error al obtener el tiempo inicial");
    exit(EXIT_FAILURE);
}

if(clock_gettime(CLOCK_REALTIME, &tEnd) == -1){
    printf("Error al obtener el tiempo final");
    exit(EXIT_FAILURE);
}
\end{lstlisting}
\vspace{2ex}

Finalmente, se calcula el tiempo transcurrido y se muestra por la salida estándar:
\begin{lstlisting}[style=cppStyle]
elapsedTime = (tEnd.tv_sec - tStart.tv_sec) + 
              (tEnd.tv_nsec - tStart.tv_nsec) / 1e+9;
printf("Elapsed time (%d repetitions): %.6f seconds\n", 
        N_ITERATIONS, elapsedTime);
\end{lstlisting}

\subsection{Implementación del algoritmo}
El algoritmo implementado corresponde al filtro de inversión en escala de grises. Para cada píxel de la imagen, la función \texttt{filter} calcula una luminosidad ponderada a partir de las componentes RGB, utilizando los coeficientes definidos previamente. El valor resultante se invierte respecto al brillo máximo y se asigna a las tres componentes del píxel en la imagen de salida:

\begin{lstlisting}[style=cppStyle]
void filter (filter_args_t args) {
    for (uint i = 0; i < args.pixelCount; i++) {
        data_t L = *(args.pRsrc + i) * R_WEIGHT + 
                   *(args.pGsrc + i) * G_WEIGHT + 
                   *(args.pBsrc + i) * B_WEIGHT;
        
        L = MAX_BRIGHTNESS - L;

        *(args.pRdst + i) = L;
        *(args.pGdst + i) = L;
        *(args.pBdst + i) = L;
    }
}
\end{lstlisting}

Dado que el tiempo de ejecución debía situarse entre 8 y 15 segundos, se realizó un bucle de 125 iteraciones de la función \texttt{filter} para mantener el tiempo dentro del rango esperado:
\begin{lstlisting}[style=cppStyle]
for (int i = 0; i < N_ITERATIONS; i++) {
    filter(filter_args);
}
\end{lstlisting}

\section{Flujo de trabajo y metodología de desarrollo}
Todo el desarrollo del proyecto se encuentra disponible en el repositorio de \textit{GitHub}: \href{https://www.github.com/Mendana/teamwork-ac-2025}{ver repositorio}. Para garantizar un trabajo colaborativo eficiente, se estableció un flujo de trabajo común basado en las herramientas \textit{Git} y \textit{GitHub} como elementos centrales de control de versiones. Los aspectos clave son:

\begin{itemize}
    \item \textbf{Repositorio compartido:} Contiene el código, la documentación y los recursos del proyecto.
    \item \textbf{Issues:} Cada tarea se define como una \textit{issue} en \textit{GitHub}, asignada a un responsable con una fecha límite.
    \item \textbf{Project Board:} Se emplea un tablero \textit{Kanban} con las columnas \textit{To Do}, \textit{In Progress}, \textit{Review} y \textit{Done} para visualizar el progreso del trabajo.
    \item \textbf{Milestones:} Cada entrega del proyecto se asocia a un \textit{milestone} que agrupa las \textit{issues} relacionadas.
    \item \textbf{Pull Requests:} Todas las contribuciones se integran mediante \textit{pull requests}, revisadas y aprobadas por, al menos, tres de los cuatro miembros del equipo antes de fusionarse en la rama principal.
    \item \textbf{Documentación:} Se conserva en la carpeta \texttt{docs/}.
\end{itemize}

\subsection{Metodología}
\label{anexo:metodologia}
El equipo adoptó una metodología ágil adaptada al contexto académico, inspirada en un enfoque híbrido entre \textit{Scrum} y \textit{Kanban}. Los elementos principales de esta metodología son:
\begin{itemize}
    \item La planificación se organiza en \textbf{iteraciones} (\textit{milestones}) que corresponden a las entregas del proyecto.
    \item Las tareas se dividen en \textbf{issues} manejables, priorizadas según su relevancia y dependencias, y se asignan a los miembros del equipo.
    \item El \textbf{Project Board} facilita la visualización del progreso y la gestión eficiente de las tareas.
    \item La revisión colectiva de los \textit{pull requests} promueve la calidad del código y el aprendizaje conjunto.
    \item Las dependencias entre tareas se gestionan mediante etiquetas y referencias cruzadas en \textit{GitHub}.
\end{itemize}
