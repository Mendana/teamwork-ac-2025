\section{Introducción}
Esta memoria recoge el desarrollo del proyecto de la asignatura \textit{Arquitectura de Computadores}, impartida en el curso 2025-2026 en la Escuela de Ingeniería Informática de Oviedo. El proyecto tiene como objetivo aplicar los conocimientos adquiridos en la asignatura para diseñar e implementar un filtro de imágenes en lenguaje \texttt{C/C++}. Además, se ha de analizar el rendimiento del filtro y compararlo las implementaciones monohilo y multihilo.\vspace{2ex}

\noindent El trabajo se ha estructurado en varias fases progresivas:
\begin{itemize}
    \item \textbf{Entrega 1 (Monohilo):} Implementación básica del filtro de imágenes en un solo hilo.
    \item \textbf{Entrega 2 (SIMD y Multihilo):} Optimización del filtro utilizando instrucciones SIMD y paralelización con múltiples hilos.
\end{itemize}

\section{Flujo de trabajo y metodología de desarrollo}
\label{anexo:workflow}

Este anexo describe la metodología de desarrollo colaborativo empleada durante el proyecto, incluyendo las herramientas utilizadas, el flujo de trabajo con Git y GitHub, y las buenas prácticas implementadas para garantizar la calidad del código.

\subsection{Organización del equipo}

El equipo se organizó siguiendo una metodología ágil adaptada, con roles específicos para cada miembro:

\begin{itemize}
    \item \textbf{Project Lead \& Backend Developer:} Diego Díaz Mendaña - Coordinación general y desarrollo core
    \item \textbf{SIMD Specialist \& Performance Analyst:} Pablo García Pernas - Optimización vectorial
    \item \textbf{Infrastructure \& Testing Lead:} Mateo Rama García - Setup de entorno y testing
    \item \textbf{Documentation \& QA Manager:} Fernando Suárez Fernández - Documentación y calidad
\end{itemize}

\subsection{Herramientas de desarrollo colaborativo}

\subsubsection{Control de versiones}
Se utilizó \textbf{Git} como sistema de control de versiones, con \textbf{GitHub} como plataforma de colaboración. La estrategia de branching siguió un modelo adaptado de Git Flow:

\begin{itemize}
    \item \texttt{main}: Rama principal con código estable
    \item \texttt{feature/*}: Ramas para nuevas funcionalidades
    \item \texttt{docs/*}: Ramas específicas para documentación
    \item \texttt{infra/*}: Ramas para configuración e infraestructura
\end{itemize}

\subsubsection{Gestión de tareas}
Todas las tareas se gestionaron mediante \textbf{GitHub Issues} utilizando plantillas específicas:
\begin{itemize}
    \item Plantillas para código, documentación, testing e infraestructura
    \item Sistema Kanban con GitHub Projects (To Do → In Progress → Review → Done)
    \item Etiquetado por prioridad, tipo y complejidad
\end{itemize}

\subsection{Proceso de desarrollo}

\subsubsection{Workflow de código}
\begin{enumerate}
    \item Creación de issue con plantilla correspondiente
    \item Asignación y creación de rama \texttt{feature/nombre-tarea}
    \item Desarrollo con commits atómicos y descriptivos
    \item Pull Request con plantilla obligatoria
    \item Code Review por al menos un compañero
    \item Merge tras aprobación y tests exitosos
\end{enumerate}

\subsubsection{Estándares de calidad}
\begin{itemize}
    \item \textbf{Code Review obligatorio:} Revisión por pares antes de merge
    \item \textbf{Testing sistemático:} Tests unitarios y de rendimiento
    \item \textbf{Documentación continua:} Actualización en cada cambio
    \item \textbf{Convenciones de código:} Estilo consistente y comentarios descriptivos
\end{itemize}

\section{Herramientas de análisis y profiling}
\label{anexo:tools}

\subsection{Herramientas de medición de rendimiento}

\subsubsection{Timing y benchmarking}
\begin{itemize}
    \item \textbf{gettimeofday()}: Medición de alta precisión
    \item \textbf{clock\_gettime()}: Timing monotónico
    \item \textbf{Scripts personalizados}: Automatización de benchmarks
\end{itemize}

\subsubsection{Profiling de memoria}
\begin{itemize}
    \item \textbf{Valgrind (massif)}: Análisis de uso de memoria
    \item \textbf{Valgrind (memcheck)}: Detección de memory leaks
    \item \textbf{/proc/self/status}: Monitoreo en tiempo real
\end{itemize}

\subsubsection{Análisis de rendimiento del procesador}
\begin{itemize}
    \item \textbf{perf stat}: Estadísticas de hardware counters
    \item \textbf{perf record/report}: Profiling detallado
    \item \textbf{gprof}: Profiling tradicional de funciones
\end{itemize}

\subsection{Comandos típicos de análisis}

\begin{lstlisting}[style=cppStyle]
# Benchmarking básico
time ./release/programa input.jpg output.jpg

# Análisis con perf
perf stat -e cycles,instructions,cache-misses ./release/programa

# Memory profiling
valgrind --tool=massif ./release/programa input.jpg

# CPU profiling
perf record -g ./release/programa
perf report
\end{lstlisting}
